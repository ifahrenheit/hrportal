# PIM "Employee 360" tabs

The PIM profile (`/pim/<employee_id>`, `pim_profile` in `app.py`) already showed the profile,
schedule, attendance summary, CSAT, leaves, file requests, leave balance, punches and memos.
Three more tabs fill in the rest of the picture:

| Tab | Shows | Source |
|---|---|---|
| **Discipline** | Incident reports about the employee; undertime per payroll period (days, minutes, memos sent), with a "Day by day" link to the Undertime Report filtered to the employee | `incident_reports`; `undertime_cycle_state` (written by `undertime_notify.py`) |
| **Coaching** | Coaching sessions where the employee is the agent, with a link to the session and to the agent's page in Coaching | `coaching_sessions` |
| **Documents** | Documents library files tagged to the employee; Certificate of Employment requests | `hr_documents`; `coe_requests` |

Code: [modules/pim_360.py](../modules/pim_360.py), fragment template `templates/pim/_tab_360.html`.
The tab buttons and panes are added to `templates/pim/profile.html` through the Jinja global
`pim360_tabs()`. Tests: `tests/test_pim_360.py`.

## Loading

Each tab is fetched from `/pim/<employee_id>/tab/<discipline|coaching|documents>` the first time
it's opened, so PIM itself loads no slower.

## Access

Opening PIM is unchanged: admins and the PIM permission (`can_pim`). Each tab also follows its own
feature's rules, so PIM never shows more than that feature would:

- **Discipline:** always offered. The IR list uses `report_scope_conds()` from
  `modules/incident_reports.py`, which means only the reports the viewer's IR dashboard lists (a
  PIM-only sub-admin who isn't a supervisor sees none they didn't file).
- **Coaching:** offered with Coaching or Coaching Reports. Sessions are limited by `coaching._scope()`
  (all / the viewer's team / the viewer's own); session links only where Coaching allows opening them.
- **Documents:** offered with Documents library access or CoE management. Files are limited to
  `_visible_levels()` (HR-only files also need the Memos permission); the CoE list shows only with
  `coe_can_manage()`.

A tab the viewer can't use isn't shown, and its URL returns 403.

## Undertime numbers

`undertime_cycle_state` keeps complete totals per payroll period, but its day list is cleared each
time a memo is sent, so "Days since last memo" only covers the days after the latest memo. The
Undertime Report (linked) has every day. Undertime is only recorded since the daily check went live.
